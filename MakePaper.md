# How the paper is made

This file records the process used for the group-delay paper, so a future
paper can follow the same steps. The first paper produced this way is the
draft of *Group-Delay Equalization for Complex IIR Filters*.

## 1. Overview

The paper passes through four stages:

1. **Working notes.** While the research is under way, results are logged
   in Markdown notes in the repo root, such as `ScldGD.md` and
   `Eqlzr_scld_results.md`.
2. **A long Markdown draft.** `doc/CmplxFltrGrpDly.md` holds all the
   material, with LaTeX maths, tables and figures. It is deliberately
   longer than the page limit, so nothing is lost before choosing what to
   cut.
3. **Rendered drafts for review.** `tools/render_paper.py` turns the
   Markdown into an HTML page (for Chrome) and a PDF (typeset by
   pdflatex).
4. **The submission (later phase).** The long draft is reduced to the
   conference's page limit and rewritten in IEEE LaTeX (`IEEEtran`).
   This stage has not been done yet; section 7 lists the plan.

Every number and every figure in the paper is regenerated by a script in
`examples/`. Nothing is typed in by hand from memory.

## 2. Keeping the paper private until the conference

The repo on GitHub is **public**, and the paper must not appear there
before the conference.

- The following are listed in `.gitignore` and never committed:
  - the draft source, `doc/CmplxFltrGrpDly.md` (covered by `/doc/*`);
  - the figures, in `doc/figures/`;
  - the rendered copies, in `tools/build/` and `doc/CmplxFltrGrpDly.{html,pdf}`.
- They live only in the Dropbox copy of the repo
  (`/home/Dropbox/Matlab/Complex/KM_ComplexFilterToolbox`), which is
  their backup.
- The scripts and library functions that make the numbers and figures
  **are** committed. They are ordinary toolbox code, and anyone can
  re-run them.
- **Before 2026-09-25 the draft was committed.** Its early versions are
  still in the git history (commits `42f2ab8` to `aa31323`). They are not
  visible when browsing the repo, but anyone who opens those commits can
  see them. For a future paper, add the ignore rules **before** the first
  commit of the draft.
- **After the conference:** remove the ignore rules for the paper, force-add
  the final files if wanted (`git add -f`), commit and push.

## 3. Tools

| Tool | Used for | Install |
|---|---|---|
| MATLAB | designs, numbers, figures | as installed (R2024b here) |
| pandoc (3.x) | Markdown to HTML and to LaTeX | `sudo apt install pandoc` |
| pdflatex (TeX Live) | LaTeX to PDF | already on the machine |
| Chrome | viewing the HTML (MathJax, needs internet) | optional |
| poppler-utils | `pdftotext`, `pdfimages`, `pdftoppm` for checking the PDF | optional |

`render_paper.py` needs the `pandoc` program on the PATH. The PyPI package
called `pandoc` is only a Python interface to that program and does not
include it.

## 4. Writing the Markdown draft

The conventions below keep the draft easy to convert to IEEE LaTeX later.

- **Maths:** use `$...$` inline and `$$...$$` for display equations.
  - Number display equations with `\tag{n}`, starting at 1 and in
    order, and refer to them as "Eq. n".
  - Keep text labels out of the maths.
  - Renumbering is easiest with a small script: shift every `\tag{}` and
    every "Eq. n" reference together.
- **Tables:** use pipe tables, with units in the header.
  - State whether group delay is in samples or in % of its mean. Mixing
    the two confused earlier drafts.
- **Figures:** write `![caption](figures/<name>)` with **no extension**.
  - The LaTeX build picks `<name>.pdf` (vector) and the HTML build picks
    `<name>.png`.
  - Each figure needs a sentence in the text saying what to look at.
- **File names:** implementation file names appear in the long draft (for
  example `lib/equiGdDigitalAp_scld.m`). In the IEEE version they belong in
  one "Implementation" paragraph or a footnote to the repo, not in the
  running text.
- **Sections used so far:**
  1. Introduction
  2. Method 1
  3. Method 2
  4. The z-to-x transform
  5. Step-by-step reference
  6. Best examples
  - Still to add: an abstract, a limitations section, a conclusion and
    references.

## 5. Numbers and figures

### Numbers

Each table in the draft comes from a script that prints it:

| Draft section | Script | Run time |
|---|---|---|
| §6.1 table (Method 1, 9 filters) | `examples/equiGd_Ap_scld.m` | ~12 min |
| §4.2 and §6.2 z vs x tables | `examples/shrink_peakNewton_scld.m`, `examples/shrink_eqlzr_scld.m` | minutes |
| all paper numbers in one run | `examples/paper_examples_scld.m` | ~20 min |

Run a script in batch mode from the repo root:

```
matlab -nodisplay -nosplash -batch "addpath('lib'); addpath('examples'); equiGd_Ap_scld"
```

**Re-run the tables after any algorithm change.** For example, after the
selection fix in `equiGdDigitalAp_scld`, the §6.1 table was re-run. One
row (`1_15_0`) changed from holding Ap to missing it, and the text had to
change from "all nine" to "eight of the nine". A table assembled from
runs made before and after a fix can be wrong.

**Check claims against the code.** Before a description of an algorithm
step goes in, read the function that implements it. An early draft said
the extremum search used a band-scaled grid when it actually uses a fixed
one.

### Figures

`examples/paper_figs_scld.m` writes every figure into `doc/figures/` as
`<name>.pdf` and `<name>.png`. It takes about 5 minutes.

| Figure | Content |
|---|---|
| `fig_m1_mag` | Method 1, `1_10_0`: magnitude of the final design (Ap held at wp) |
| `fig_m1_gd` | Method 1, `1_10_0`: group delay of the final design |
| `fig_m2_mag` | Method 2: magnitude after equalization with 5 clusters of 5 sections (unchanged from before, by construction) |
| `fig_m2_gd0` | Method 2: group delay of the primary reference filter before equalization |
| `fig_m2_gd` | Method 2: group delay after equalization with 5 clusters of 5 sections |
| `fig_m2w_mag` | Method 2, wide band (`csc_fltr_1_8_0`): magnitude after equalization (7 clusters of 5) |
| `fig_m2w_gd0` | Method 2, wide band (`csc_fltr_1_8_0`): group delay before equalization |
| `fig_m2w_gd` | Method 2, wide band (`csc_fltr_1_8_0`): group delay after equalization (7 clusters of 5) |

Figure rules (set by the author):

- Each figure shows **one design**: the final best one, or (for Method 2)
  the filter before equalization, in its own figure.
- Each figure has **two solid curves**, the passband zoom and the full
  band, in the **same units**: dB for magnitude, samples for group delay.
- There are no band-edge marker lines (`markEdges` false) and no
  stopband masking (masking breaks the curve into dashes).
- The two y-axes are aligned: 0 dB is at the same height in both
  magnitude views (`alignZero`), and the maximum group delay in the zoom
  window is at the same height in both group-delay views (`alignMax`).
  Both are on by default. The group-delay zoom's range covers its whole
  window, so peaks just outside the passband are not clipped.
- Frequency axes are labelled in Hz (the sample rate is taken as 1 Hz,
  so the numbers equal cycles/sample); group delay stays in samples.

The plotting functions are in `lib/`:

- **`plotMgTwo(H, wp, ws, opts)` and `plotGdTwo(H, wp, ws, opts)`** plot
  the magnitude and the group delay of 1–3 filters.
  - Each draws the **passband zoom** (blue, bottom and left axes) and the
    **full band** (red, top and right axes) in a single axes box, to save
    space.
  - Line style tells the filters apart, so the figures still work in
    black and white.
  - Useful options:
    - `names` for the legend;
    - `Ap`, which limits the zoom range of the magnitude plot;
    - `zoomRelPct`, which makes the group-delay zoom show % deviation, for
      filters whose delays differ;
    - `maskDb`, which hides stopband group delay;
    - `file`, which exports the figure.
- **`plotTwo(c1, c2, title, opts)`** is the shared engine: two overlaid
  axes in one box.
- **`savePaperFig(fig, file, widthIn, heightIn, fontSize)`** does the export.
  - It sizes the figure to one IEEE column (3.5 in wide by 2.8 in high,
    8 pt text) and thins the lines.
  - It refits the axes so labels on all four sides fit, with the legend
    in a strip underneath.
  - It writes a vector PDF and a 300 dpi PNG.

After making a figure, **look at it** by opening the PNG. The first
versions had problems that only showed when viewed:

- two designs at different delays flattened each other's ripple;
- a reference line was misleading;
- the legend covered the curves.
- an example's magnitude figure was never written at all: the text and
  the built PDF (with figure numbers auto-assigned from source order)
  both looked plausible on their own, and the gap only showed up when
  the PDF was read start to end and a figure number was missing. Check
  the figure count against the figure script's own list, not just that
  the ones present look right.

## 6. Rendering and checking a draft

```
tools/render_paper.py                 # tools/build/ and doc/ copies (HTML + PDF)
tools/render_paper.py --view html     # and open the HTML in Chrome
tools/render_paper.py --pdf-only --view pdf
```

What the script does:

- It runs pandoc twice: to HTML with MathJax, and to LaTeX with
  `amsmath`, `geometry` and `hyperref`.
- It gives each build the right figure type
  (`--default-image-extension`), and copies `doc/figures/` into the build
  folder so pdflatex and the HTML can find the figures.
- It runs pdflatex until the cross-references settle.

Quick checks on the PDF:

```
pdfinfo tools/build/CmplxFltrGrpDly.pdf | grep Pages
pdftotext tools/build/CmplxFltrGrpDly.pdf - | grep -n "^Figure"      # captions present
pdfimages -list tools/build/CmplxFltrGrpDly.pdf                       # empty = figures are vector
pdftoppm -f 10 -l 10 -r 60 -png tools/build/CmplxFltrGrpDly.pdf page  # look at a page
```

## 7. The IEEE version

**Status (2026-09-25): the generator is in place** (`tools/make_ieee_tex.py`,
YAML content plus `string.Template` layouts). `doc/make_tex_flow.md`
explains the whole flow.

- **Full length:** `doc/ieee/CmplxFltrGrpDly_full.yaml` gives a 10-page
  IEEE-format version with all the detail. It was converted from the
  Markdown draft by `tools/md2ieee_yaml.py`, then edited by hand.
- **Submission:** `doc/ieee/CmplxFltrGrpDly_conf.yaml` will be cut down
  from the full version to the page limit.

The plan below still applies to the cut-down version.

This is the plan; it has not been done yet.

1. Decide the page limit and what goes, usually by moving material out:
   - the "Alternatives investigated" subsections (§2.2 and §3.2);
   - most of §5 (the step-by-step reference);
   - file names.
   Some of this could go into a companion technical report or the repo.
2. Start from pandoc's LaTeX output (`render_paper.py --keep-aux` keeps the
   `.tex`) or convert by hand into an `IEEEtran` conference template.
   - Replace `\tag{n}` with `equation` environments and `\label`/`\eqref`.
   - Turn tables into `table` environments and figures into `figure`
     environments with `\label`/`\ref`.
   - Add the abstract, keywords and a BibTeX bibliography.
3. Keep the figures as they are: they are already one column wide
   (3.5 in), in vector PDF with 8 pt text. Re-run
   `examples/paper_figs_scld.m` if any design changes.
4. Keep the IEEE `.tex` next to the Markdown draft in `doc/`, where the
   ignore rules keep it out of git until after the conference.

## 8. Checklist for a new paper

1. Add `.gitignore` rules for the draft, its figures and its renders
   **before** the first commit.
2. Start the Markdown draft in `doc/`, following section 4.
3. For every table or number, write or name the script that prints it,
   and record it in this file's section 5.
4. Write a figure script that uses `plotMgTwo`, `plotGdTwo` and
   `savePaperFig`, and view each PNG.
5. Render with `tools/render_paper.py` (pass the new Markdown file as the
   argument) and run the checks in section 6.
6. Re-run every number-producing script after the last algorithm change,
   before submission.
7. Convert to IEEE LaTeX (section 7) and cut to the page limit.
8. After the conference, lift the ignore rules and publish.
